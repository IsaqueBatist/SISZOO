# Decisões — T37 (lançamento de resultado no processo sanitário)

Uma linha por decisão, no formato de `T29.md`. Resolve a pendência R1 da
T29 ("task de resultado substitui o `PATCH /status` provisório, D18") e o
objetivo 4 do roteiro da T37 (histórico em vez de reedição).

## Decisões

- **DH-11** "Sem resultado ainda" tem uma única representação:
  `resultado_laboratorial_id IS NULL`. O catálogo `aguardando` continua
  existindo no seed (nenhuma migration o remove), mas `POST /{id}/resultado`
  recusa (422) esse código como valor escolhido — não é um resultado válido
  para lançar, só o estado inicial do catálogo.
- **DH-12** `PATCH /api/processos/{id}/status` deixa de aceitar a transição
  `AGUARDANDO_RESULTADO → COM_RESULTADO` (422, mesmo sendo "um passo"). Essa
  transição só acontece via `POST /{id}/resultado`, que grava resultado,
  data e desfecho do animal na mesma escrita. As demais transições do D18
  continuam pelo `PATCH /status`.
- **DH-13** Resultado é write-once: o trigger `tg_processo_sanitario_resultado_imutavel`
  (V14) recusa qualquer `UPDATE` de `resultado_laboratorial_id`,
  `data_resultado` ou `desfecho_animal_id` depois do primeiro lançamento,
  para qualquer caminho (inclusive SQL manual — mesma garantia do DH-7 da
  T29). **Não existe hoje um fluxo de retificação** (corrigir um resultado
  errado exigiria uma migration própria para alterar ou contornar esse
  trigger); isso fica para uma task futura, se o CCZ precisar.
- **DH-14** O desfecho do animal é travado junto com o resultado, no mesmo
  lançamento (`POST /{id}/resultado`). Não há um segundo momento para só
  informar o desfecho depois — se vier vazio no lançamento, fica `null` e
  também passa a ser imutável (mesma trigger da DH-13).
- **DH-15** Notificação por e-mail dispara para `positivo` **e**
  `inconclusivo` (regra 19 do DER, confirmada pelo usuário). Roda fora da
  transação de escrita: o service publica `ResultadoLancadoEvent` e um
  listener `@Async`/`@TransactionalEventListener(AFTER_COMMIT)` dispara a
  notificação depois do commit, numa thread separada — uma falha ou demora
  de SMTP não pode manter o lock de `findByIdForUpdate` nem a resposta HTTP
  esperando.
- **DH-16** Município: tentativa real via `JavaMailSender`/`spring-boot-starter-mail`
  (infraestrutura nova). Melhor esforço — se não há e-mail cadastrado no
  responsável, só loga e não tenta enviar; se o envio falhar (SMTP
  indisponível, timeout), a falha é só logada (`log.warn`), nunca propaga.
  O resultado já foi salvo antes deste listener rodar, então uma falha de
  e-mail nunca desfaz nem bloqueia o lançamento.
- **DH-17** Vigilância Epidemiológica de Itu: **mockada**. Não existe
  endereço real configurado para esse destinatário — o código só loga a
  intenção (`[MOCK] notificação à Vigilância Epidemiológica...`), sem
  tentativa de envio real. Quando o CCZ informar um endereço/config, trocar
  o mock por um envio real é a mesma mudança que o `enviarAoMunicipe` já
  faz.
- **DH-18** Histórico do processo (objetivo 4 da T37): como só existe UM
  resultado por processo (write-once, sem tabela de múltiplos lançamentos),
  não há uma lista de "vários resultados" para mostrar. `GET /{id}/historico`
  devolve a trilha de auditoria (`CRIACAO`/`ATUALIZACAO`) desse processo,
  sem payload nem dado pessoal — é "quando/quem", não "o quê mudou". Esse
  endpoint é novo e protegido por `PROCESSOS_SANITARIOS:leitura`, não por
  `USUARIOS_ACESSO:leitura` (que só o Administrador tem) — Veterinário e
  Agente Sanitário também precisam ver a trilha do processo que eles mesmos
  lançam.
- **DH-19** `galNumero`/`sinanNumero`/`dataEnvioAmostras`/`previsaoRetorno`
  não entram no contrato desta task (decisão explícita, fora do escopo da
  T37) — ficam para quem implementar o fluxo real de envio de amostras.

## Pendências para tasks seguintes

- Fluxo de retificação de um resultado lançado incorretamente (DH-13) — hoje
  não existe; exigiria alterar o trigger da V14.
- Endereço real da Vigilância Epidemiológica de Itu (DH-17) — quando
  disponível, substitui o mock por um envio real.
- `galNumero`/`sinanNumero`/`dataEnvioAmostras`/`previsaoRetorno` (DH-19).
